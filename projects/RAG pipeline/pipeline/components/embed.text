## TWO PASS DEPLOY OF cloudrunon the two pass deploy explain to me the steps: then ill paste the cloudbuild.yaml file.

Two-pass deploy steps:

    1. First deploy — build the image (with the placeholder your-service-xxxxx.run.app hostname still in mcp_wrapper.py), push it, and run terraform apply (or gcloud run deploy) to create the Cloud Run service for the first time.
    2. Get the real URL — Cloud Run assigns the actual hostname only once the service exists (e.g. rag-pipe-mcp-mcp-server-abc123-ew.a.run.app). Retrieve it via gcloud run services describe or from Terraform's output (if you add one to outputs.tf).
    3. Update mcp_wrapper.py — replace the placeholder in allowed_hosts with that real URL.
    4. Second deploy — rebuild the image with the corrected hostname, push it again, and redeploy (Cloud Run will just update the existing service, no new Terraform resource needed since the service already exists — just a new image revision).

After that, every future deploy is single-pass, since the hostname stays stable (Cloud Run URLs don't change on redeploy, only if you delete/recreate the service).
